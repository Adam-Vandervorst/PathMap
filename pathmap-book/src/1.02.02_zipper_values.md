# Value Access
Several traits provide access to values stored in the trie.  These trais are distinguished by the lifetimes available on the returned values, and by the ability to access values at arbitrary paths or only at the focus.

- [`ZipperValues`] is avilable on most zipper types, and provides short-lived access to values at the current focus.
- [`ZipperValuesAt`] provides access to values at arbitrary descendant paths relative to the focus without moving the zipper.
- [`ZipperReadOnlyValues`] is only available on zippers that cannot modify the trie, and provides access to the same values but with a lifetime parameter tied to the backing data structure, allowing the zipper to be moved or even dropped while the borrow remains active.
- [`ZipperReadOnlyConditionalValues`] makes lifetime guarantees that compromise between [`ZipperValues`] and [`ZipperReadOnlyValues`]. It uses a witness object to ensure the underlying values remain intact while still allowing zipper movement.

## ZipperValues
The [`ZipperValues`] trait provides zippers with the ability to borrow values of type `V` at the current focus position.

- [`val`] returns an `Option<&V>` - `Some` containing a reference to the value, if one exists at the focus, or `None` otherwise.

### Basic Value Access

```rust
# extern crate pathmap;
use pathmap::{PathMap, zipper::*};

let mut map = PathMap::new();
map.insert(b"users/alice", 42);

let mut zipper = map.read_zipper();
zipper.descend_to(b"users/alice");
assert_eq!(zipper.val(), Some(&42));
```

The returned reference borrows the zipper, which means you cannot modify or move the zipper while the borrow is active. For longer-lived references that survive zipper movement, use [`ZipperReadOnlyValues`] and [`ZipperReadOnlyConditionalValues`].

## ZipperValuesAt
The [`ZipperValuesAt`] trait provides access to values at paths below the zipper's current focus without requiring the zipper's focus to be moved.

Virtual tries may not be able to support returning long-lived references to values at arbitrary trie paths.  Often because those values don't exist anywhere in memory.  Therefore the [`ZipperValuesAt`] trait tends to be limited to zippers over tries that are fully backed by a materialized structure.

- [`val_at`] returns an `Option<&V>` - `Some` containing a reference to the value if one exists at the path, or `None` otherwise.

## ZipperReadOnlyValues
The [`ZipperReadOnlyValues`] trait provides the same value access as [`ZipperValues`] but with a lifetime parameter that is tied to the source of the value, irrespective of the zipper.  The zipper may be modified or even dropped, and the borrow remains valid.

This trait is implemented on read-only zipper types where the underlying data structure's lifetime can be guaranteed, and will never be implemented alongside [`ZipperWriting`] on the same type.

- [`get_val`] returns an `Option<&V>` - `Some` containing a reference to the value if one exists at the focus, or `None` otherwise.

- [`get_val_at`] returns an `Option<&V>` - `Some` containing a reference to the value if one exists at the path, or `None` otherwise.

## ZipperReadOnlyConditionalValues
The [`ZipperReadOnlyConditionalValues`] trait provides an intermediate approach between [`ZipperValues`] and [`ZipperReadOnlyValues`]. It uses a witness object to ensure the underlying values remain intact, while still allowing zipper modification.

- [`witness`] returns an object to guarantee validity of borrows made using [`get_val_with_witness`].

- [`get_val_with_witness`] returns an `Option<&V>` - `Some` containing a reference to the value if one exists at the focus, or `None` otherwise.

### Witness-Based Access
The trait introduces a [`witness`] method that returns a `WitnessT` type, which acts as a proof that the underlying data remains valid. The [`get_val_with_witness`] method then provides a reference with the witness's lifetime rather than relying on a borrow from the zipper.

This design allows the zipper to be moved while ensuring that any borrowed values remain valid as long as the witness remains active.

### Example Usage
```rust
# extern crate pathmap;
use pathmap::{PathMap, zipper::*};

// Create a PathMap and populate it
let mut map = PathMap::new();
map.insert(b"hello", "world");
map.insert(b"hello/nested", "value");

// Convert to a read-only zipper
let mut zipper = map.into_read_zipper(b"");

// Move to a position with a value
zipper.descend_to(b"hello");
assert!(zipper.is_val());

// Create a witness to enable extended lifetime access
let witness = zipper.witness();

// Get a reference using the witness
let value_ref = zipper.get_val_with_witness(&witness).unwrap();

// The zipper can now be moved while the value reference remains valid
zipper.descend_to(b"/nested");
assert!(zipper.is_val());

// The original value reference is still valid because the witness is alive
assert_eq!(*value_ref, "world");

// Get another value using the same witness
let nested_ref = zipper.get_val_with_witness(&witness).unwrap();
assert_eq!(*nested_ref, "value");

// Both references remain valid until the witness is dropped, even after the
// zipper is dropped
drop(zipper);
assert_eq!(*value_ref, "world");
assert_eq!(*nested_ref, "value");
```
